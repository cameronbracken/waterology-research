# Waterology 0.8.0

This release adds a project reproducibility mode and makes the lighter mode the
default. Work is reproducible when the code is committed, the environment is
pinned in a lockfile, and a README or task explains how to run it.

- Add `reproducibility = "light" | "strict"` to `waterology.toml`. A missing key
  means `light`. The setting is left out of execution fingerprints, so saved
  study hashes do not change.
- Report the mode from `waterology config context <skill>`.
- Define both modes once in `project-conventions`. In `light` mode, skills skip
  claim and task ledgers, environment gates, lifecycle labels, audit verdicts,
  deliverable reproduction, routine independent reviews, and automatic
  constraint runs unless the user asks.
- Use worktrees in `light` mode only for concurrent writers or a dirty checkout.
- Keep statistical design rules for simulation studies and the managed study
  gates for autoresearch and engineering in both modes.

Set `reproducibility = "strict"` for replication packages, publication
deliverables, and projects that need the previous behavior.
