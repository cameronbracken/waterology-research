# Markdown delivery

Apply when producing a Markdown artifact, not to choose the task's workflow.

- Use `.md` for simple readable text and preserve the destination's existing
  structure. Prefer underscores for emphasis and leave blank lines around
  headings, lists, and code fences.
- Use named Markdown links rather than bare URLs. Use meaningful labels,
  relative paths within a portable artifact bundle, and descriptive alt text
  in Markdown image embeds. Keep linked files beside the
  deliverable or in the project's established artifact directories.
- Link sources and credit authors. Prefer scholarly citations when available,
  otherwise use the repository or a stable source page. Do not invent references.
- For Markdown artifacts the user needs to review, open the finished file with
  the `open` CLI on macOS when a desktop session is available. Otherwise provide
  a clickable file link. Do not add a viewer dependency to create a text file.
