# Notes

Use [writing-style](../writing-style/SKILL.md) and
[Markdown delivery](../writing-style/references/markdown-artifacts.md).
Read optional local guidance with `waterology config context markdown-notes`, or use the
[local resolver](../project-conventions/references/local-preferences.md).

- Keep the note proportional to the request. Prefer a short title and a few
  paragraphs, bullets, or checkboxes; do not add report scaffolding.
- Preserve existing task status, dates, decisions, and user wording where
  useful. Distinguish facts, open questions, and proposed next actions.
- Use `- [ ]` and `- [x]` for todos. Add owners or deadlines only when known.
  Link supporting artifacts rather than copying long logs into the note.
- Use the established project notes location or the user's chosen destination.
  Do not assume a private vault path or copy notes into another system.

For an explicitly requested session log, research diary, or restart handoff,
use [session-log](../session-log/SKILL.md) instead of adding its workflow to
every note. Load a visual skill only when the user also requests creating or
changing a visual; an existing image link does not make a note a report.
